# Research — Native agent worker runtime (E003)

## Per-agent isolation via Electron utilityProcess
Electron's `utilityProcess.fork()` is the blessed isolation primitive for N (5–15) long-lived, network-bound agent workers — over `child_process.fork` (no Chromium-services isolation / `getAppMetrics`) and `worker_threads` (no crash containment; one crash/OOM kills the main process). It gives a real OS process (true crash containment, SIGTERM kill, exit/error lifecycle), full Node for provider SDKs, structured IPC via `parentPort`/`MessagePortMain`, per-agent visibility in `app.getAppMetrics()`, and `--max-old-space-size` via `execArgv`. It mirrors the per-process isolation node-pty already gives Claude agents (`src/main/pty.ts`: spawn → `onExit` → `setExitHandler` teardown/archive). Sources: Electron utilityProcess docs; SAD ADR-0003.

## Native agentic loop + Stop-equivalent continuation
The canonical loop is request → model returns tool_use → execute tool locally → append tool_result → repeat until end-of-turn. With no Claude Code Stop hook off-CLI, the autonomy must be reproduced inside the worker: at end-of-turn the worker calls back into the hive drain (`src/main/hive.ts` `drainForStop(agentId)` → `{ block, reason }`); if it returns block (fresh inbox), inject the drain reason as the next turn and continue; else go idle. A `stop_hook_active`-equivalent guard (don't re-drain a turn a drain itself created) plus hop/turn caps prevent infinite loops — exactly the guard `src/main/hooks.ts` applies for Claude. Sources: SAD ADR-0004; HIVE.md autonomy loop.

## ProviderRuntime-fronted worker + normalized AgentEvent IPC
The worker is fronted by the E001 `ProviderRuntime` port (`src/shared/providerRuntime.ts`) so every downstream consumer (avatars, telemetry, breaker, hive) treats a native agent identically to a Claude agent. The loop emits the normalized `AgentEvent` stream (`src/shared/agentEvent.ts`) over IPC — turn/thinking/text-delta/tool-start/tool-end/token-usage (cumulative-monotonic)/api-error/stop. The actual provider model call is a pluggable seam the loop invokes; E003 ships the seam + a stub provider to drive the loop end-to-end, and E006 implements the real DeepSeek/Minimax adapters. Bounded per-worker memory + event-queue backpressure + a floor-wide concurrency cap keep the fleet stable. Sources: SAD ADR-0001/0002/0003; E001 contracts/provider-runtime-contract.md.
