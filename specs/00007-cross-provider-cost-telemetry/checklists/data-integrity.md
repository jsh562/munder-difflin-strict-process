# Data Integrity Checklist: Cross-Provider Cost Telemetry
**Created**: 2026-06-09 | **Feature**: [spec.md](../spec.md)

Requirements-quality checklist ("Unit Tests for English") for the Data Integrity domain of E007. Each item interrogates whether the cost/normalization invariants are clearly, completely, consistently, and measurably specified — not whether code satisfies them.

## Compute-Once Invariant

- [X] CHK001 Do the requirements unambiguously define "the single usage seam" as a single named point, such that there is exactly one place USD is set? [Clarity, FR-001/AD-001] <!-- Evaluator: Covered by spec.md §Glossary (Usage seam) + plan.md §Summary/AD-001 (collector publish in telemetry.ts) -->
- [X] CHK002 Is the term "downstream" defined concretely (which consumers — ledger, breaker, renderer, waterfall — are downstream) so "never recomputed downstream" is testable? [Measurability, FR-002/HINT-001] <!-- Evaluator: Covered by plan.md §Key Constraint + §Integration Points (FR-014) + HINT-005 — ledger/breaker/renderer/waterfall enumerated -->
- [X] CHK003 Do the requirements state the exact compute formula (Σ tokens × registry price) precisely enough that two implementers would produce the same USD for the same input? [Clarity, FR-001/SC-001] <!-- Evaluator: Covered by spec.md FR-001/SC-001 + research.md §3 (USD = Σ(tokens_k × price_k)) -->
- [X] CHK004 Is it specified whether USD is computed at the collector publish step versus at sample creation, so "computed once" pins a concrete moment in the data flow? [Ambiguity, AD-001/HINT-001] <!-- Evaluator: Covered by plan.md AD-001 + HINT-001 (computed at the collector publish) -->
- [X] CHK005 Do the requirements define what may legitimately retain `claude_code.cost.usage` (a diagnostic cross-check) versus what is forbidden (using it as the cost source), without contradiction? [Consistency, AD-001/FR-005] <!-- Evaluator: Covered by plan.md AD-001 + HINT-001 (diagnostic only) + spec.md FR-005 (never the source) -->
- [X] CHK006 Is "compute once" reconciled with cumulative accumulation — i.e., is it clear that USD is recomputed per cumulative sample yet never recomputed by a downstream consumer of that sample? [Consistency, FR-002/FR-010] <!-- Evaluator: Resolved — clarified spec.md §Glossary "Compute-once" (once per published cumulative sample at the seam, never re-derived downstream) -->
