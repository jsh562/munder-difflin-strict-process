# Research — Provider and model registry (E002)

## Data-driven, dated pricing registry
A provider/model registry for a multi-vendor harness should be a maintainable data/config artifact (not hardcoded constants), keyed by provider + model id, carrying context window, endpoint, origin, capabilities, and **dated** price rows. Dating matters because vendors run rotating promos and deprecate model ids on fixed schedules, so a stale flat table silently mis-bills. The registry is the single source consumers read; adding a provider/model is a data change, not a consumer-code change. Replaces the existing `src/main/pricing.ts` family-string lookup whose `DEFAULT_PRICE = SONNET` mis-prices any non-Anthropic model. Sources: SAD ADR-0005; src/main/pricing.ts.

## Provider pricing/capability facts (seed values, confirm at build time)
DeepSeek reports a **cache hit/miss split** (`prompt_cache_hit_tokens` vs `prompt_cache_miss_tokens`), so price rows need cache-read and cache-write/miss columns. Minimax M3 prices by **context-length tier** (calls under a ~512K-token threshold bill standard, above bill a higher long-context rate), so a price row needs an optional context-size threshold. Both DeepSeek and Minimax are ~1M-context-class; both lack uniform support for image input, MCP tools, web search, and prompt caching over their endpoints — the capability descriptor must declare these as unsupported. Exact GA per-token prices (esp. Minimax M3) and cache-field availability are not fully confirmed and need a build-time spike. Sources: SAD ADR-0005/ADR-0008; provider research brief (DeepSeek/Minimax fact sheet).

## Fail-loud lookup, replacing the Sonnet default
The load-bearing correctness rule: an unknown model id must **fail loud** (surface a warning/error) rather than default to another vendor's price — the current `priceFor()` defaulting unknown ids to Sonnet is a correctness bug for non-Anthropic models. Cost stays computed once from token counts × the selected price row (mirroring the existing `estimateCostUsd` contract), with best-effort degradation only when a usage *field* (e.g. cache split) is missing — never the price. Existing Claude cost behavior must not regress when the registry supersedes the family-string table. Sources: SAD ADR-0005; src/main/pricing.ts (`priceFor`, `estimateCostUsd`).
